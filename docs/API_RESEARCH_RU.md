# Исследование Lua API grandMA2 3.9

Дата исследования: 6 ноября 2026. Цель — установить, какие данные нужны для переноса группы пикселей в Layout, и отделить подтверждённые возможности от предположений.

## Официальные источники

1. [Plugins](https://help.malighting.com/grandMA2/en/help/key_plugins.html), версия 3.9: механизм плагинов использует Lua.
2. [Edit Plugins](https://help.malighting.com/grandMA2/en/help/key_plugins_edit.html), версия 3.9: источник перечня специальных функций — **поставляемый `plugins/plugin_1.lua`**. Руководство также объясняет импорт пары XML/Lua. Путь onPC: `C:\ProgramData\MA Lighting Technologies\grandma\gma2_V_x.x.x\plugins\plugin_1.lua`.
3. [Release Notes 3.1](https://help.malighting.com/grandMA2/en/help/release_notes/key_rn_v3.1.html): при введении плагинов заявлены Lua 5.3 и API/примеры в поставке. Это историческое основание выбора Lua, а не подтверждение свойств Layout в каждой сборке 3.9.
4. [Layouts](https://help.malighting.com/grandMA2/en/help/key_layouts.html), версия 3.9: Layout является двумерным представлением объектов.
5. [Edit Layout](https://help.malighting.com/grandMA2/en/help/key_layouts_edit.html), версия 3.9: документированы позиция/размер/стиль и **Image/Icon Rotation**. Из этого не следует наличие универсального свойства поворота группы сабфикстур.
6. [Export](https://help.malighting.com/grandMA2/en/help/key_keyword_export.html) и [Import](https://help.malighting.com/grandMA2/en/help/key_keyword_import.html), версия 3.9: поддержаны обмен XML и `/path`; у Export есть `/schema`. В прототипе используются явный объект назначения и путь, без `/overwrite`, `/noconfirm`, смены диска или текущего command destination.
7. [Позиции приборов в Stage](https://help.malighting.com/grandMA2/en/help/key_patch_position_fixtures.html), версия 3.9: трёхмерные координаты и повороты относятся к сцене. Они не используются как позиции Layout.

Веб-руководство **не содержит исчерпывающей таблицы Lua-свойств Layout**. Официальная установленная grandMA2 3.9 и её локальный `plugin_1.lua` в рабочей среде отсутствуют. Поэтому здесь нельзя честно утверждать, что прямое чтение координат дочерних Layout-элементов проверено на реальной 3.9, или что оно принципиально невозможно.

## Дополнительная проверка формы API

Для сверки сигнатур прочитана [копия образца MA `plugin_1.lua`](https://github.com/chienchuanw/gma2-plugins/blob/dev/reference/ma-samples/plugin_1.lua) в стороннем репозитории, blob `414dcd9609cf97751f05ea5f01b54571bd4b53e1`. Парный XML имеет метаданные **3.0.187**, поэтому эта копия **не подтверждает принадлежность образца к 3.9** и не заменяет файл из установленной станции. В образце есть используемые `gma.cmd`, `gma.textinput`, `gma.feedback`, `gma.sleep`, `gma.show.getobj.*`, `gma.show.property.amount/name/get`. Метода записи `property.set` в перечне этой копии нет; прототип его не вызывает.

Форма дескриптора MA2 — `<Plugin ... luafile="имя.lua"/>`, без структуры ComponentLua из MA3. Она сверена с [парной копией plugin_1.xml](https://github.com/chienchuanw/gma2-plugins/blob/dev/reference/ma-samples/plugin_1.xml), blob `5b0308e7e3a7b3cc285007c8e13d10db6526f074`. Чужой исходный код в проект не включён.

Для проверки идеи XML использованы первичные сообщения авторов на форуме производителя: [Command Line Entry](https://forum.malighting.com/forum/thread/29986-command-line-entry/) с примерами экспорта/импорта Layout и [Remove deleted items from layout views](https://forum.malighting.com/forum/thread/31955-remove-deleted-items-from-layout-views/) с фрагментом `LayoutSubFix`. Это сообщения пользователей, **не контракт API MA Lighting** и не доказательство совместимости с 3.9. Связка `Subfixture fix_id / sub_index` дополнительно сверена с [исходником генератора XML его автора](https://github.com/szymonplotkowski/GrandMA2---Python-lib/blob/master/ma2_python_lib.py); его версия 3.4 также не подтверждает формат каждой сборки 3.9. Поэтому тестовый XML в проекте явно обозначен как синтетический, а reader останавливается на неизвестной структуре.

## Матрица доступности

| Нужные данные/действия | Lua/API или команда | Что установлено | Решение прототипа |
| --- | --- | --- | --- |
| Handle Layout/Fixture | `gma.show.getobj.handle("Layout N")`, `handle("Fixture N")` | Сигнатура сверена по образцу; конкретные объекты проверяются на станции | Доступ к Layout проверяется перед экспортом |
| Дети объекта | `getobj.amount`, `getobj.child` | Можно запросить дерево; нет гарантии, что все Layout-элементы представлены детьми | Только диагностика, индексы детей от 0, обход ограничен |
| Имена/значения свойств | `property.amount`, `property.name`, `property.get` | Механизм чтения есть; состав свойств зависит от объекта/сборки | Перечисление имён вместо придуманных PosX/Rotation и числовых констант |
| Layout X/Y | В XML `LayoutSubFix center_x / center_y` | Известен формат из примеров, но он не проверен здесь экспортом 3.9 | Строгое распознавание структуры и отдельная onPC-проверка |
| Связь элемента с пикселем | В XML `Subfixture fix_id / sub_index` | В примерах используется идентификатор прибора и индекс | Явное сопоставление raw-индексов; отсутствие `sub_index` — отдельный ключ `root` |
| Поворот группы пикселей | Готовое Lua-свойство не установлено | У группы точек может не быть единственного stored-угла | Математический поворот координат вокруг выбранного центра |
| Image/Icon Rotation | UI в официальном руководстве | Это настройка изображения/иконки | Сохраняется исходное значение; не применяется к группе |
| Stage Pos/Rot | Свойства Fixture/Stage | Другая система координат | Не используются и не меняются |
| Модель/режим/порядок модулей | Полный универсальный механизм не подтверждён | Одинаковое число элементов недостаточно | Совместимость и порядок выбирает оператор |
| Изменение шоу | `gma.cmd` + Import | Команда импорта документирована; результат cmd не считается квитанцией успеха | Подтверждение, новый слот, повторный экспорт для проверки |

## Почему не распознавать сторону и угол автоматически

Симметричная линейка даёт направление только с неоднозначностью 180°. Матрица может иметь несколько осей симметрии. Из одних координат без физического порядка модулей нельзя вывести, какой пиксель является первым, и требовалось ли отражение. Кроме того, визуальное положение справа/слева не определяет электрический порядок пикселей.

Оператор задаёт угол источника `αs` и конечный угол цели `αt`. Для точки `p` и центров `cs`, `ct` используется:

```text
local = R(-αs) · (p - cs)
local = M · local
result = ct + R(αt) · local
```

`M` — единичная матрица, `diag(-1,1)` для `flip_x` или `diag(1,-1)` для `flip_y`. Отдельный список индексов цели отвечает за перенумерацию, не изменяя формулу геометрии. Масштаб не меняется. При `αs=30°`, `αt=-30°`, `M=I` получается относительный поворот на `−60°`.

## Что должна подтвердить реальная станция

Режим `probe` печатает версию Lua, доступные build-метаданные и свойства указанного Layout/Fixture. Это **read-only**: только чтение API и Feedback. Он не экспортирует файлы и не вызывает `gma.cmd`. Обход ограничен глубиной 2, 200 объектами и 256 свойствами на объект. Не найденное при таком обходе свойство не объявляется недоступным вообще.

На точной сборке 3.9 следует сверить используемые функции с её локальным `plugin_1.lua`, экспортировать **реальный** Layout и при необходимости его `/schema`, проверить raw-индексы на изолированных пикселях и пройти [протокол испытания](TESTING_RU.md). Только после этого можно расширять адаптер для прямого API, автоматической типизации или разрешённого изменения существующих Layout.
