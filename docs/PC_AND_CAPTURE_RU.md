# Установка на ПК и Layout по проекту Capture

Обновление 0.2.0 от 7 ноября 2026. Указанная пользователем среда: grandMA2 **3.9.63.10**, Capture **2024**. Нужны отдельные Layout спереди и сверху. Совпадение ID пока не подтверждено экспортами.

Доступна облачная Linux-среда. Доступа к Windows-ПК пользователя, его экрану и открытым проектам нет. Файлы из другого чата также не предоставлены. Установка на этом ПК, испытание onPC и Layout конкретной сцены **ещё не выполнены**. Подготовлены исходники, установщик и проверенный на синтетических данных путь переноса координат.

## Установка файлов на Windows

В распакованном проекте запустите из PowerShell:

```powershell
.\tools\Install-LayoutAssistant.ps1
```

Без параметров скрипт только показывает найденные каталоги MA2 3.9. После проверки фактического пути:

```powershell
.\tools\Install-LayoutAssistant.ps1 -PluginsDirectory "C:\ProgramData\MA Lighting Technologies\grandma\gma2_V_3.9.63.10\plugins" -WhatIf
.\tools\Install-LayoutAssistant.ps1 -PluginsDirectory "C:\ProgramData\MA Lighting Technologies\grandma\gma2_V_3.9.63.10\plugins"
```

Путь выше — пример, а не обнаруженный каталог вашего ПК. Скрипт создаёт новую папку с уникальным именем, копирует Lua/XML, не перезаписывает предыдущие версии и не управляет запущенной onPC. PowerShell-установщик в Windows ещё не испытан. Если политика выполнения скриптов запрещает запуск, вручную скопируйте два файла из `dist/` в новую папку внутри `plugins`, не меняя политику системы.

В onPC: **Edit пустого Plugin-слота → Import → новая папка → layout_assistant.xml**. Execute on Load оставьте выключенным. Если импортёр не показывает подпапку, используйте новую пару на USB в `gma2/plugins`. Существующие одноимённые файлы не заменяйте без проверки.

Первый запуск: `probe` → `preview` на копии шоу → проверка TXT → `create` в свободный слот. Реальный экспорт 3.9.63.10 ещё не проверен.

## Исходные данные для вашей сцены

1. **Capture 2024 → File → Export Fixture Data → CSV/TSV** с номерами приборов и координатами. Сохраните исходные заголовки. Если координат в CSV нет, нужен дополнительный экспорт grandMA2 XML или MVR для последующей адаптации; текущий конвертер MVR не читает.
2. Экспорт существующего Layout из MA2 с нужными приборами и пикселями. Например, `Export Layout N "LA_source_20261107"`, где `N` — фактический номер, а имя файла ещё не занято. Если Layout ещё нет, сначала нужен новый черновик в свободном слоте; недостающие пиксельные модули из одного Capture CSV версия 0.2.0 не создаёт.
3. Скриншоты Capture **спереди и сверху**, желательно ортографические, с номерами приборов, осями/направлением зрителя и одним известным размером. Они нужны для проверки сторон и визуального масштаба. Перспективный скриншот не заменяет точные координаты и соответствие Fixture ID.

В [руководстве Capture 2024](https://www.capture.se/Manual/en-UK/2024/FileMenu.html#export-fixture-data) описаны CSV/TSV и отдельный экспорт grandMA2 fixture data. Последний относится к патчу/слоям, а не готовому Layout. Для нашей задачи импорт в EditSetup не требуется. В описании MVR на той же странице Channel (FixtureID) и Unit (UnitNumber) различаются: считать их одним номером автоматически нельзя.

## Профили площадок и два вида

Профиль JSON содержит соответствие колонок CSV, две оси проекции, знаки осей, начало координат, масштаб и необязательную карту ID. `examples/venue-front.json` и `venue-top.json` — **синтетические примеры** с условными Z вверх и Y в глубину; проверьте оси и направление зрителя по своему проекту.

Создайте папку `out/`, затем выполните из корня проекта:

```sh
python3 tools/capture_csv.py examples/scene-synthetic.csv examples/venue-front.json out/scene_front.tsv
python3 tools/capture_csv.py examples/scene-synthetic.csv examples/venue-top.json out/scene_top.tsv
lua5.3 tools/offline.lua examples/synthetic-layout.xml out/scene_front.tsv out/front.xml
lua5.3 tools/offline.lua examples/synthetic-layout.xml out/scene_top.tsv out/top.xml
```

Для собственных данных замените CSV, профиль и XML. Существующие выходные файлы не перезаписываются. Python нужен только для внешней конвертации; внутри MA2 плагин автономен.

Конвертер выдаёт TSV и JSON-отчёт. TSV — данные, не исполняемый Lua. Строгий заголовок: `fix_id<TAB>x<TAB>y<TAB>rotation_delta`, где `<TAB>` означает настоящий символ табуляции.

`x,y` — новый центр набора элементов в единицах Layout. `rotation_delta` — добавочный поворот уже существующего рисунка пикселей в плоскости Layout, по умолчанию 0. Это **не Euler-угол Capture**: положение корпуса, pan/tilt и 3D-матрица требуют отдельного преобразования.

Центр рассчитывается как `(координата оси − origin) × scale × знак`. Размер рисунка пикселей и иконок сохраняется: `scale` увеличивает расстояние между центрами приборов. Для другой нумерации добавьте `id_map`, например `{"12":101,"13":201}`. При наличии карты каждое входное ID должно в ней присутствовать. Без карты отчёт явно обозначает предположение о совпадении ID.

Ошибки колонок, пустые координаты, повторяющиеся ID, NaN/Infinity и несуществующие в Layout приборы останавливают операцию. Совпадающие после проекции центры отмечаются в JSON: приборы на разных глубинах могут наложиться во фронтальном виде. Автоматического раздвигания пока нет.

## Режим scene внутри MA2

1. Скопируйте `scene_front.tsv` и `scene_top.tsv` в выбранный каталог `importexport`.
2. Плагин → `scene` → исходный Layout → каталог → `scene_front.tsv` → `preview`.
3. Проверьте TXT, повторите с `create` и подтвердите свободный слот.
4. Для верхнего вида повторите с **тем же исходным Layout** и `scene_top.tsv`, выбрав другой свободный слот. Повороты не должны накапливаться от результата первого вида.

Каждый прибор переносится со всеми его fixture-элементами в Layout, относительно среднего их центров. Если мастер-модуль не должен влиять на центр, используйте черновик без него либо offline-рецепт `placements` с явным `indices`. Секции можно предварительно подготовить режимом копирования шаблона. Недостающие ID сначала должны быть добавлены в черновой Layout оператором.

## Что дорабатывать дальше для художника по свету

| Приоритет | Возможность | Польза |
| --- | --- | --- |
| 1 | Библиотека шаблонов FixtureType + DMX mode + индексы, по проверенным экспортам | Перенос стробов, баров и матриц между шоу без повторной карты |
| 1 | Графический preview с ID, цветом типов и наложениями | Проверка сторон сцены и удобства выбора до импорта |
| 2 | Опорные точки и смещения слоёв/ферм | Читаемый Layout тесной сцены с сохранением исходных координат |
| 2 | Таблица соответствия Capture Channel/Unit/UUID и MA2 ID | Контроль перепатча и touring-шоу |
| 2 | Сохранение последних параметров мастера рядом с шоу | Повторный выпуск без ввода всех данных |
| 3 | Импорт матриц MVR/glTF с проекцией локальных осей | Корректные углы сложных конструкций вместо догадки по RotZ |
| 3 | Согласованный diff существующего Layout с резервной копией | Обновление готового шоу после подтверждения изменяемых объектов |

В 0.2.0 уже есть профили проекции, карты ID, два независимых вида, TSV-сценарий и проверки импорта. Возможности в таблице пока не реализованы.
