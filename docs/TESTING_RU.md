# Проверка и приёмка на grandMA2 3.9

## Автоматические проверки

Из корня проекта:

```sh
python3 tools/build.py
python3 tools/check.py
```

Используется реальный интерпретатор Lua 5.3; при другой версии проверка выпуска остановится. Lua выбирается через `LUA`, затем `lua5.3`, затем `lua`. Стандартные библиотеки Python используются для сборки и независимого чтения результата XML.

Набор `tests/run.lua` проверяет:

- одинаковые и противоположные углы, локальное отражение, обратный порядок пикселей, нестандартный центр, несколько шаблонов;
- сохранение расстояний в 500 воспроизводимых случайных преобразованиях;
- сохранность незадействованных XML-фрагментов и различие `root`/`0`;
- чтение атрибутов в одинарных/двойных кавычках, комментарии, сущности без раскрытия, ограничения формата;
- отказ при другой версии, нескольких экспортированных объектах, дубликатах, отсутствующем модуле, несовпадающей длине и конфликтующих назначениях;
- ноль команд в probe, отсутствие Import в preview, отмену мастера и подтверждения;
- занятый слот, занятый после диалога слот, изменившийся источник, изменённый файл результата;
- успешный цикл через mock-транспорт, ошибки экспорта/импорта, неправильный результат проверки;
- отказ от перезаписи файлов, опасных командных строк и загрузку собранного Lua без `package/require` станции.

`tools/check.py` дополнительно проверяет актуальность сборки, дескриптор именно MA2 (`luafile`, Execute on Load выключен), синтаксис всех Lua, полный offline-сценарий, повторный запуск с отказом от перезаписи и валидность XML/SVG стандартным XML-parser Python.

Mock не эмулирует MA2, её импорт, session-синхронизацию, UI или точность чисел. Пройденный тест адаптера подтверждает ветвления нашего кода, а не работоспособность команды на реальном устройстве.

## Протокол ручного испытания

Все действия ниже оператор выполняет самостоятельно в **отдельной копии тестового шоу**. Не меняйте существующие рабочие объекты ради испытания. Запишите полную версию MA2, тип станции, режим Standalone/Session и фактический путь importexport. Первое испытание — Standalone без параллельных изменений.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Откройте локальный `plugins/plugin_1.lua` своей установки 3.9 | Используемые функции доступны; зафиксирована точная сборка |
| 2 | Импортируйте пару dist-файлов через редактор пустого Plugin-слота, Execute on Load выключен | Импорт сам не запускает мастер |
| 3 | В тестовом шоу подготовьте новый Layout, два аналогичных пиксельных прибора и посторонний объект с подписью | Все нужные пиксели уже в Layout; исходные координаты известны |
| 4 | Запустите `probe` для Layout и Fixture | Feedback показывает свойства/доступные build-данные; ни одного объекта/файла не создано |
| 5 | Сделайте ручной Export Layout с новым именем; отдельно экспортируйте один заранее известный пиксель в тестовом Layout | Установлено соответствие отображаемого `Fixture N.M` и XML `sub_index`; формат совпадает с reader |
| 6 | При необходимости вызовите `Export Layout <номер> "новое_имя" /schema /path="<каталог>"` | Получена схема именно своей сборки; файлы не перезаписаны |
| 7 | Расположите шаблон под известным `+30°`; запустите preview с конечным `−30°`, mirror=none | Сохранены снимок, новый XML/TXT; в шоу ничего не изменилось |
| 8 | Проверьте TXT и при желании создайте SVG внешним tools/preview.py | Центр цели сохранён, расстояния совпадают, индексы соответствуют физическому порядку |
| 9 | Запустите create и отмените на подтверждении | Import не выполнен |
| 10 | Попробуйте указать занятый слот, включая исходный | Плагин остановился до импорта |
| 11 | Выполните create в пустой слот с точным `CREATE N` | Создана копия всего Layout, исходный не изменён; проверка координат завершилась |
| 12 | Повторите с flip_x/flip_y, асимметричной фигурой и отдельной обратной нумерацией | Геометрическое отражение не смешивается с перестановкой индексов |
| 13 | Повторите для второго типа/DMX-режима со своим шаблоном | Работает его явная карта модулей, нет предположения о фиксированном количестве |
| 14 | Измените исходный Layout во время последнего диалога create | Обнаружено изменение снимка; Import не выполнен |
| 15 | Сравните исходный и новый Layout, подписи/иконки/размеры, Programmer и Stage | Менялись только запланированные центры в новой копии; импорт мог нормализовать формат XML |

Для проверки зеркальности используйте минимум три неколлинеарные точки: линейка сама по себе не доказывает сохранение или изменение ориентации двумерной формы.

Если формат XML иной, сохраните обезличенный экспорт и диагностику и адаптируйте reader вместе с fixture-тестом. Не подставляйте наугад PosX, числовые индексы API или функции MA3. При недоступном каталоге исправьте путь/доступ; не включайте автоматическое изменение выбранного диска.

```text
onPC / console / Mode2:
Standalone / Session:
Lua _VERSION / build metadata:
Локальный plugin_1.lua сверён:
Путь importexport:
Тип и DMX-режим прибора A:
Тип и DMX-режим прибора B:
Соответствие Fixture N.M -> XML sub_index:
Preview / отмена / занятый слот:
Поворот +30 -> -30 / отражение / перестановка:
Create и повторный экспорт:
Точность экспортируемых координат:
Исходный Layout / посторонние элементы / Programmer / Stage:
Найденные отличия и обезличенные файлы:
```

Не публикуйте рабочие show-файлы и данные проекта вместе с отчётом без отдельного разрешения их владельца.
